# Research Report Indexing

This directory configures the report-index layer adapted from the upstream `xbtlin/ai-berkshire` implementation introduced in September 2026 and hardened in October 2026.

The indexer does not modify report bodies. It produces two derived artifacts:

- `reports/README.md`: a human-readable report directory for GitHub.
- `reports/index.json`: a machine-readable inventory for scripts or downstream search.

## Safe publication order

A report must be represented in Git's index before it can appear in the generated public index:

```bash
git add reports/path/to/report.md
python3 tools/reports_index.py
git add reports/README.md reports/index.json
```

Then commit the report and generated index in the same change.

Use check mode after generated artifacts exist:

```bash
python3 tools/reports_index.py --check
```

Check mode is read-only. It returns a non-zero exit status if the committed generated files do not match the currently staged/tracked report set.

## Why Git-index membership matters

Scanning the working directory alone can expose local drafts in a generated public index even when those drafts were never intended for publication. The adapted implementation therefore:

- includes committed reports and normally staged new reports;
- excludes untracked and ignored files;
- excludes `git add -N` / intent-to-add placeholders whose contents are not staged;
- fails closed when Git index state cannot be read;
- forces `core.quotePath=false` when reading history so Unicode paths receive stable commit dates regardless of a developer's local Git configuration.

These invariants are covered by `tests/test_reports_index.py` using temporary real Git repositories.

## Metadata

Metadata is inferred in this order:

1. YAML front matter (`title`, `date`, and optional `type`).
2. Date embedded in the filename or parent directory.
3. Date near the beginning of the report body.
4. Latest Git commit date for the path.

A first-level Markdown heading is preferred for the display title. If none exists, the filename is used.

## Classification

`config.json` maintains aliases and known top-level buckets for companies, themes, investors/thinkers, screening pools, and other preserved archive areas. The historical archive remains primarily in its original language, so the configuration intentionally retains its existing Unicode directory names.

Unlisted top-level directories default to company classification and are reported by the generator so maintainers can decide whether they belong in another bucket.

## Root README integration

The generator can also refresh summary blocks in the root README, but only when the following explicit markers are present:

```text
<!-- REPORTS-BANNER:START generated by tools/reports_index.py -->
<!-- REPORTS-BANNER:END -->

<!-- REPORTS-INDEX:START generated by tools/reports_index.py -->
<!-- REPORTS-INDEX:END -->
```

This fork does not require those markers. Keeping root-README integration opt-in prevents an upstream archive feature from rewriting the English-first product-facing README unexpectedly.
